## How we communicate

- Main channel: [WhatsApp / Slack / Discord — pick one]
- Daily check-in: one short message by 9pm each day — what you finished, what's next, anything blocking you.
- If you're stuck for more than an hour, say so in the channel before burning more time alone on it.
- No one is expected to reply after 10pm. Mornings are fine.

## Deadlines

- Every task on the board has an owner and a due day, not just "this week."
- If you're going to miss a task's deadline, flag it in the channel *before* it's due, not after.
- Board status gets updated the same day work happens — not batched at the end of the week. This is a hard rule from the brief, not just a nice-to-have.

## Decision-making

- Small technical calls (naming, styling details): whoever owns the task decides, no vote needed.
- Bigger calls (schema changes, dropping a feature, changing the tech approach): quick discussion in the channel, majority of active members agree, Frontend Lead breaks ties.

## Conflict resolution

1. Raise it directly with the person first — most things are a misunderstanding, not a real conflict.
2. If it's not resolved in a day, bring it to the group channel and talk it through together.
3. If it's still stuck, the PM/QA role facilitates a 10-minute call to land on a decision everyone can live with.
4. Zero visible activity from someone for 2+ days triggers this process immediately — we don't wait for the deadline to notice.

## Commit / edit convention

`<type>: <what changed> - <why it matters>`

Examples: `feat: add stock-availability endpoint - lets the dashboard show real inventory instead of mock data`, `fix: correct order-id lookup bug - was matching partial IDs`. No "wip", no "updates", no "stuff".

## Peer Reliability Index

Confidential between each person and the evaluator. Only aggregate patterns (not individual scores) get shared back with the team.
